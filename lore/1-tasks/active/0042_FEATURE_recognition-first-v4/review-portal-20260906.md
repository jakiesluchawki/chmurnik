# Web Consultation Portal

The owner requested a friendly browser-based review with three password accounts,
not ZIP/CSV handling, and explicitly approved CyberFolks for the real panel with
a GitHub Pages entry link. This extends the consultation delivery only; it does
not authorize further ML experiments or expert outreach.

Use the existing brand and genuine 33 licensed review photos. Three isolated
reviewer accounts and one owner coordinator account. Save drafts server-side;
freeze independent answers before revealing historical/source-label reports.
The original package remains a small, exposed training-source label-quality
pilot, not an independent accuracy benchmark. Keep these limits visible.

CyberFolks supports PHP rather than static Pages authentication. No Sites
project was created; the attempted empty scaffold could not fetch dependencies
in the restricted network and was not used. No Netlify project was created.

The main app's existing service worker caches successful GETs regardless of
response cache headers. Therefore every sensitive portal request, including
photo retrieval and session reads, uses same-origin authenticated POST, which
the existing service worker does not intercept. No change to the app's cache
or user data is necessary. Protected responses additionally use no-store.

Credentials and review data must never enter public Git, Pages, ZIP release
assets, client JavaScript or localStorage. Only private owner delivery may
contain installation/account material. Publishing a login screen is not proof
that server authentication, storage and cross-account isolation work.
